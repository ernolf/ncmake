# Lint module

The lint workflows of ncmake-workflows as make targets, in `mk/lint.mk`. Each target collects the same files, runs the same tool in the same version and fails where its workflow fails, so a finding shows on the maintainer's machine before it shows in a public CI log. Which release of a tool runs, and the digest it is checked against, comes from `data/tools.json`. The targets read the checkout, write nothing into it and need no token.

| Target | What it checks |
| --- | --- |
| `make lint-actions [JSON=<file>]` | actionlint, with shellcheck over the `run:` scripts, over every tracked workflow: whether it is valid |
| `make lint-actions-security [JSON=<file>] [SARIF=<file>]` | zizmor over every tracked workflow and action definition: what makes a workflow attackable |
| `make lint-containerfiles [JSON=<file>]` | hadolint over every tracked Containerfile and Dockerfile |
| `make lint-markdown [JSON=<file>]` | markdownlint-cli2 over every tracked Markdown file |
| `make lint-php-syntax [PHP_VERSIONS="<versions>"] [JSON=<file>]` | `php -l` over every tracked PHP file, once per PHP version |
| `make lint-shell [JSON=<file>]` | shellcheck over every tracked shell script |
| `make lint-version [JSON=<file>]` | the version of `package.json`, `composer.json` and `package-lock.json` against `appinfo/info.xml` |
| `make lint-vue-imports [JSON=<file>]` | imports of the `@nextcloud/vue` root in the tracked source files |
| `make lint-web [JSON=<file>]` | ESLint, Stylelint and html-validate over the plain web files of a repository without a `package.json` |
| `make lint-yaml [JSON=<file>]` | yamllint over every tracked YAML file |
| `make lint` | every target of the module, one after the other |

Every target collects its files with `git ls-files`, as its template does, and leaves out `node_modules/` and `vendor/` where the template does. A configuration of the tool in the repository wins; without one, `lint-markdown`, `lint-web` and `lint-yaml` apply the default of their template. A repository without files of the kind passes. `[!]` marks what fails the template and exits 1, `[i]` what passes it: a warning of ESLint, Stylelint, markdownlint or yamllint (unless the yamllint configuration sets `strict`), a hadolint finding below its `failure-threshold` (`info` unless the configuration sets one), and a warning or deprecation of `php -l`. Every error of actionlint, every finding of shellcheck in a shell script and every finding of `lint-version` and of `lint-vue-imports` is `[!]`; a shellcheck finding in a `run:` script is `[!]` with the severity error or warning and `[i]` with info or style. Each finding names file, line, rule and the page of the rule. Each target takes `ARGS=--json` and `JSON=<file>`, and `ARGS=--details` lists the files it checked.

`lint-actions` checks what `lint-actions-security` checks, without the action definitions, and reads the repository's actionlint configuration; without one it declares the self-hosted runners of Nextcloud, as `data/github-runners.json` names them, as known runner labels. It hands the `disable=` and `enable=` of the repository's `.shellcheckrc` on to the shellcheck actionlint runs, which reads none itself, gives a shellcheck finding the line and column it has in the workflow, and marks untrusted input in a `run:` script with `"security": true`. `lint-shell` takes every `*.sh` and `*.bash`, and every other file whose shebang names sh, bash, dash or ksh, and reads `.shellcheckrc`. `lint-containerfiles` takes `Containerfile`, `Dockerfile`, `*.containerfile` and `*.dockerfile` and reads the repository's hadolint configuration. `lint-vue-imports` finds a static or dynamic import, a re-export, a `require` and a `vi.mock` or `jest.mock` of the root, in `.vue`, `.js`, `.mjs`, `.cjs`, `.jsx`, `.ts`, `.mts`, `.cts` and `.tsx` files; an entry point such as `@nextcloud/vue/components/NcButton` passes. `lint-version` compares `version` of `package.json` and `composer.json` and `version` and `packages[""].version` of `package-lock.json` with `<version>` of `appinfo/info.xml` as written, skips a file that states none, marks a manifest that is not valid JSON `[!]`, and passes a repository without `appinfo/info.xml`. `lint-web` passes a repository with a `package.json`, which lints through its own scripts, and leaves out minified `*.min.js` and `*.min.css`. With `RUNTIME=bare` a configuration of the repository finds the packages of `lint-markdown` and `lint-web` as in the container, after those of the checkout's own `node_modules/`, and nothing is written into the checkout. `lint-php-syntax` checks the PHP versions of `PHP_VERSIONS`, of a `.php-version` file or the default, separated by spaces, commas or semicolons, and refuses a word that is not digits and dots; the default is, in an app, the floor and the ceiling `php-compat` derives, and `8.2 8.4` elsewhere; a parse or fatal error is `[!]` under the version that reports it.

The tools are the releases `data/tools.json` names: actionlint, shellcheck, hadolint and zizmor as the Linux binaries of their GitHub releases, checked against their sha256 digests; yamllint with pathspec and PyYAML as source distributions from PyPI, checked against their digests, which run on the Python of the analysers' Node image without pip; markdownlint-cli2, ESLint, Stylelint and html-validate installed by npm in the analysers' container, each at the version `data/tools.json` names and checked against the integrity the registry records. All of them are kept in `tools/` of the ncmake cache, fetched once per version and mounted read-only, so the host needs none of them; a version a newer one supersedes is removed once no ncmake container runs. `lint-php-syntax` runs each version in `docker.io/library/php:<version>-cli-alpine`. With `RUNTIME=bare` the tools run on the host: an npm package whose `engines.node` the host's Node does not meet stops the run with that range, and `lint-php-syntax` runs the host's `php<version>`, or its `php` when that is the version, and reports a version it has neither for as not run.

`lint-actions-security` checks the tracked files under `.github/workflows` and `.ncmake/workflows`, every `action.yml` or `action.yaml` outside `node_modules/` and `vendor/`, and every YAML file with a `.properties.json` beside it, the form of a workflow template. zizmor runs offline and reads the repository's own configuration. Findings of medium and high severity are `[!]` and exit 1, low and informational ones `[i]`; each names file and line, the zizmor audit and its page, and whether the audit describes an attack or hardening, as `lib/actions-security-audits.json` of ncmake sorts every audit of the zizmor release. Only an attack carries `"security": true` in the JSON; a hardening finding, such as an action not pinned to a commit, keeps its level and still fails, and an audit the table does not know yet counts as an attack. `SARIF=<file>` writes the findings for GitHub code scanning as well. The zizmor binary is the one of its GitHub release, checked against its digest, kept in `tools/` of the ncmake cache and run in the analysers' Node container, so the host needs neither zizmor nor Node. A repository without workflows passes.

`make lint` runs each target in a make of its own, so a failed one does not stop the next, and fails when one failed. `ARGS`, `JSON=` and `SARIF=` belong to a single target, and `make lint` refuses them. `make help-<target>` lists every option of a target.
